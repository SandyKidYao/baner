# ADR-0008:密钥存成本机私有文件

## 背景

ADR-0006 选了系统钥匙串。行走骨架中实测(2026-11-10):
- ad-hoc 签名:重新构建后读取被拦,弹出授权框(用户两次点「允许」)。
- 换成自签名证书「Baner Local Signing」,并由用户手动设为「代码签名:始终信任」:先删除旧条目,由构建 n1 重新写入,构建 n2 读取时仍然阻塞约 10 秒,弹窗出现。
- 原因:macOS 钥匙串条目带「分区列表」。签名里没有 Apple 开发者团队 ID 的应用(自签名也属于这种),分区只能是 `cdhash:`,每次构建都会变。要得到稳定的团队 ID,必须加入付费的 Apple Developer Program(每年 99 美元),与 D7「零费用」冲突。

用户要求不要弹窗(「这不还是得弹出来让我点吗」),决定换方案。

## 选项

### 选项 A:继续用钥匙串,接受每次更新后弹一次窗
- 用户拒绝。

### 选项 B:Apple Developer Program
- 与零费用冲突。

### 选项 C:本机私有文件(采用)
- `~/Library/Application Support/<应用标识>/secrets.json`,文件权限 0600,目录权限 0700。
- 必须在数据目录(git 工作区)之外,代码层面强制检查。
- 内容:git token、解开的 age 文件钥匙(ADR-0004)。

## 决定

采用 C(用户 2026-11-10 确认)。ADR-0006 标为 superseded。

## 理由

- 用户的核心威胁模型是「git 仓库被人下载」。C 完全满足:仓库里只有密文,钥匙不在仓库里。
- 完全不弹窗,符合「配置一次就不再打扰」。
- 与 SSH 私钥(`~/.ssh/id_*`)、git 凭据存储是同一种做法。

## 后果

- 正面:跨平台实现一致(Android 上放在应用私有目录,其他应用天然无法读取);不再需要代码签名证书,README 少了一步。
- 负面与代价:以用户身份运行的其他程序(包括恶意程序)可以读取这个文件,比钥匙串弱。在这个前提下,恶意程序同样能记录键盘输入、读取已解密的内容,所以实际差距有限。
- 什么情况下应该重新审视:要分发给其他人时(那时值得买开发者账号,再换回钥匙串),或者用户对本机安全的要求提高。
